# Project structure (backend repository)

A tour of every folder and root file, and where to go to change something. Read this first.

EduPlatform has two repositories ([ADR-0013](../adr/0013-separate-frontend-and-backend-repositories.md)):

| Repository | What it holds |
|---|---|
| **eduplatform-backend** (this one) | Services, API host, worker, device gateway, database, the API contract, all design documents |
| **eduplatform-frontend** | Web app and super admin console. It knows the backend only through a copy of the API contract |

## The big picture

```
Browser ──► frontend (other repository)
                       │  HTTP, with the user's token
                       ▼
            apps/api   (host: runs the services)
              ├── services/audit
              ├── services/…           one package per business service
              └── packages/server-kit  shared plumbing
                       │
                       ▼
                 PostgreSQL 18   one schema per service, Row-Level Security per tenant

apps/worker          background jobs (outbox relay, imports, …)
apps/device-gateway  receives punches from biometric devices
packages/contracts   the API contract: Swagger, Postman, and the file the frontend copies
```

## Folders

| Folder | What it is | You change it when… |
|---|---|---|
| `services/<name>/` | One business service (audit today; platform, identity, access … from Phase 2): its code, its tables (`migrations/`), its manifest | You build or change a feature |
| `apps/api/` | The **host**: starts NestJS, the HTTP pipeline, health checks, and the services in `src/services.ts`. Almost no business code | You register a service, or change request handling for all services |
| `apps/worker/` | Background process: moves events from each service's outbox to queues; later imports and reports | A service needs work done outside a request |
| `apps/device-gateway/` | Separate process for biometric devices (Phase 5) | Device integration |
| `packages/server-kit/` | Shared backend plumbing: request context, tenant transactions, migrations, access guard, audit writer, outbox, logging, error responses | Rarely; changes affect every service |
| `packages/contracts/` | The **API contract**: OpenAPI files per service. Generates Swagger, TypeScript types and the Postman collection | **Before** you add or change an endpoint or event (CLAUDE.md rule 7) |
| `packages/config/` | Shared TypeScript settings | Almost never |
| `infra/database/` | `roles.sql`: the database roles, used by `pnpm db:setup` and the tests | A new database role is needed |
| `infra/docker/` | Docker Compose for Postgres, Redis, Keycloak, MinIO, Mailpit. **On hold** ([ADR-0012](../adr/0012-local-development-without-docker.md)) | Phase 2 |
| `docs/` | Design documents (01–08), module documentation, guides, architecture decisions (`adr/`) | You change behaviour or make a design decision |
| `.github/workflows/` | CI: lint, format, type-check, tests, contract freshness, secret scan | You add a new kind of check |

Generated folders, never edited and never committed: `node_modules/`, `dist/`, `.turbo/`.

## Root files

| File | What it is |
|---|---|
| `package.json` | Repository commands: `pnpm dev`, `pnpm test`, `pnpm lint`, `pnpm db:setup` … |
| `pnpm-workspace.yaml` | Which folders are packages |
| `pnpm-lock.yaml` | Exact versions of every library. Generated by `pnpm install`; committed |
| `turbo.json` | Runs build, lint and test across packages in dependency order, with caching |
| `AGENTS.md` | Written by the Turborepo tool for AI coding assistants; leave it as is |
| `eslint.config.mjs` | Code rules, including "a service may import other services only through `/public`" |
| `.prettierrc.json`, `.prettierignore` | Automatic code formatting (`pnpm format`) |
| `.editorconfig`, `.gitattributes` | Same indentation and line endings in every editor and OS |
| `.gitignore` | What git never stores |
| `.nvmrc` | Node.js version |
| `.env.example` | Template for your local `.env` (never commit `.env`) |
| `.gitleaks.toml` | Secret-scan settings |
| `CLAUDE.md` | The working agreement: non-negotiable rules and naming |
| `README.md` | Front page |

## Where do I change…?

| I want to… | Go to |
|---|---|
| Add an endpoint | 1. `packages/contracts/openapi/<service>.yaml` → `pnpm contracts:build` 2. controller in `services/<service>/src/http/` 3. tell the frontend team to run `pnpm api:sync` |
| Add a table or column | New file `services/<service>/migrations/000N_<what>.sql` (never edit an applied one) |
| Add a permission | The service's `src/manifest.ts`, and the matrix in `docs/04-roles-and-permissions.md` |
| Publish an event | Schema in `packages/contracts/events/`, then `publishEvent()` inside the same transaction as the write |
| Record an audit entry | `recordAudit()` from `@eduplatform/server-kit`, inside the same transaction |
| Use another service's data | Import from `@eduplatform/<other>-service/public`, or consume its events. Never its tables |
| Add a new service | [adding-a-service.md](adding-a-service.md) |
| Run one service alone | [running-one-service.md](running-one-service.md) |
| Change how every request is handled | `apps/api/src/configure-app.ts` |
